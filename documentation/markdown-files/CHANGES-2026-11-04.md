# Graapes HRMS targeted updates — 04 Nov 2026

## Included
- Super Admin profile hides Employee ID, Department, and Designation. These fields remain visible for other employee-linked roles.
- Organization Setup now provides Delete actions for departments and designations. Deletion is blocked with a clear conflict message while employees/designations are assigned, to prevent accidental loss or broken references.
- Employee names in the directory open an employee profile detail dialog. A permanent Delete Employee action is displayed only to Super Admin.
- The employee deletion API independently enforces Super Admin authorization and removes the employee login account plus dependent database records in a transaction. Manager/head/approver references are cleared where needed. An audit event is retained.

## Database / safety
- No Prisma schema change or migration is required.
- No database cleanup or automatic deletion is run by this update.
- Department/designation delete is intentionally blocked while referenced. Reassign employees first.
- Employee permanent deletion removes related attendance, leave, correction, document/letter, notification, and employee-history database rows. External object-storage files, if any exist, are not removed by this database transaction.

- Node syntax checks passed for the changed API route files.
- Frontend production build could not be run in this environment because Vite is not installed in the extracted archive's node_modules. Run `npm install` (or `npm ci`) then `npm run build` locally before deploying.
